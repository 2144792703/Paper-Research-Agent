## 二、能力盘点

### 已经掌握并能讲清取舍

- **LangGraph 编排**：`StateGraph`、节点增量更新、条件边、`recursion_limit`、状态 TypedDict；能解释「为什么只有两处条件边」。
- **LLM 网关**：OpenAI 兼容接口、key 池轮换、429 指数退避、401/403 永久禁用、RPM 滑动窗口、流式与非流式两条路径。
- **缓存设计**：键的组成（版本/提供方+地址指纹/模型/采样参数/prompt）、空值不写不命、思考模式隔离、Windows 文件锁的处理。
- **并发**：`ThreadPoolExecutor` + `executor.map` 保序、单篇失败隔离、并发度与限流的关系、用 `perf_counter` 做前后对照。
- **服务化**：FastAPI + SSE、请求校验、单任务锁、超时降级、全局异常处理、非 root Docker + healthcheck。
- **可观测与成本**：Langfuse Trace/Span/Generation 层级、token 按模型统计、价格表优先级与部分计价。
- **测试**：pytest fixture/monkeypatch、离线与 live 隔离、混沌的确定性注入、服务端事件断言。

### 能独立实现的模块

LLM 网关（缓存 + 重试 + 限流）、7 节点论文研究工作流、SSE 服务、评估脚本、Docker 交付。给一个需求，能自己拆节点、定状态、写兜底、补测试。

### 仍薄弱

- 向量数据库与混合检索：只做过 arXiv 关键词检索，没有 embedding、rerank、chunk 策略的实战。
- 评估体系：有 20 主题脚本，但没有 faithfulness / answer relevancy 这类指标，也没有留存结果做回归。
- 异步与高并发：当前是线程池 + 单 worker，没做过 asyncio 全链路或分布式限流。
- 持久化与恢复：checkpointer 只停留在方案层。
- 上下文工程：长文档裁剪、压缩、记忆管理只有 `SELECT_SUMMARY_CHARS` 这类朴素预算。
- 前端与产品化：没有可视界面，SSE 也没有节点级进度。
- MCP / 多 Agent 协议：读过 DeerFlow 的实现，但没有自己写过 MCP server 或多 Agent 协作。

## 三、批判性复盘

### 当时取舍得当的

1. **workflow 而不是 agent**：任务步骤固定，状态机让每一步可测、可估成本；把「智能」压到开局一次路由，避免模型抖动导致环。
2. **降级优先于重试到底**：单次模型抖动不应该毁掉整次 run；三层兜底 + 质量标记，让调用方知道报告是否可信。
3. **缓存键把 provider 和 BASE_URL 指纹算进去**：换服务地址不串缓存，这是踩过坑之后补的。
4. **混沌注入复用真实重试链路**：一个开关验证换 key、退避、重试、兜底四件事，没有为测试单写一套逻辑。
5. **数字事后校验用原始摘要做语料**：不用 LLM 的二次总结自证，避免以讹传讹。

### 明确的妥协

- 只读摘要不读全文，结论受摘要信息量限制。
- 单 worker、进程内锁与统计，不能横向扩展。
- 价格表是静态快照，两个在用 Qwen 模型至今没有单价，成本只能报 token。
- 没有持久化、没有节点级 SSE 进度、没有前端。
- 评审的「通过」依赖字符串语义，虽然已兼容尾标点，但仍是脆弱契约。
- 评估脚本没有留存结果，20 主题通过率无法复现。
- 早期提交有重复与信息不统一，说明工程习惯是后补的。

### 如果重做一版会改什么

1. 第一天就把 `run_id / degraded / degraded_reasons` 放进 state，质量标记不做事后补丁。
2. 把 LLM 网关独立成模块（现在已在 `models/remote.py` 与 `llm.py`，但应更早分层），业务节点从第一天就不碰重试与缓存。
3. 先写 benchmark 与评估，再做并发和缓存优化；现在的 3.47 倍只有一次对照。
4. 用 `graph.stream` 从服务端第一天就推节点进度，而不是最后补。
5. 提交规范前置：每个 day 一次提交，提交前跑全量测试与 `git status`。

### 可写进简历的亮点（带数字）

1. 用 LangGraph 实现 7 节点论文研究流水线（2 处条件边 + 4 道终止保障），单次运行 12 次 LLM 调用、8458 tokens，支持 CLI 与 SSE 两种入口。
2. 单篇总结并发化（并发度 3），总结阶段 102.19s → 29.43s，提速 3.47 倍；同轮总耗时 192.48s → 123.33s。
3. 设计 LLM 磁盘缓存键（版本/提供方/模型/采样参数/prompt），二次运行 182.20s → 1.41s，12/12 命中、0 token、0 请求。
4. 实现 key 池与三层兜底：429 指数退避、401/403 永久禁用、4 轮遍历上限；路由/筛选/综述失败均可降级并输出质量标记。
5. 建立 48 个离线用例 + 5 个 live 用例，覆盖混沌注入、缓存边界、SSE 事件、数字校验与注入防护。

## 六、收尾

这 56 天最大的变化不是多写了几个功能，而是形成了固定动作：先定状态与失败策略，再写节点；先写确定性测试，再开混沌；提交前跑全量用例并检查工作区。项目仍有明显短板（检索深度、评估、持久化），但每一个短板都有明确的原因、代价和下一步，这比「功能很多但说不清」更接近可交付。
