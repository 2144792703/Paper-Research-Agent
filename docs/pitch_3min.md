## 逐字稿（约 500 字）

我做了一个论文研究 Agent。输入一个研究主题，它会自动检索 arXiv、筛选论文、并发做结构化总结，最后生成一份带评审意见和后续追问的中文综述。

它解决的痛点是：人工查论文、读摘要、拼综述，一轮要几个小时，质量取决于当天状态；而常见工具要么只做检索，要么只做摘要，缺少一条可复核的完整链路。

项目有三个技术点。第一，编排用 LangGraph 状态机：`supervisor` 负责路由，`search → select → summarize_one → summarize → critic → followup` 七个节点用条件边串联，用 `revision_count` 和 `critique_times` 限制评审轮数，再加确定性护栏，避免模型输出抖动导致死循环。

第二，成本与速度。路由、筛选、单篇总结走 cheap 模型，综述和评审走 strong 模型；所有模型结果按版本、模型、采样参数和 prompt 做磁盘缓存，空响应不写入也不命中。单篇总结并发度 3，总结阶段从 102.19 秒降到 29.43 秒，提速 3.47 倍。

第三，稳定性。key 池轮换，429 指数退避，401 和 403 永久禁用；路由、筛选、综述三层兜底，任一模型连续失败都降级而不是中断；混沌开关按概率注入超时，验证换 key、退避和兜底链路。

这个项目从图编排、缓存、并发、限流，到 FastAPI 的 SSE 输出和 Docker 部署，都是我自己实现并验证的，目前 48 个离线用例全部通过。我最大的收获是把「让模型跑通」变成「让流程可控」。

下一步我想补全价格表与评估体系，并把当前的串行流程扩展成可持久化的多轮研究助手。
